Partner organizations — what exists, what is only disconnected, and what was never built

Read from the code and the build history, 9 September 2026.

You were right and I was wrong. I told you what exists is "a name tag and a page with names and logos on it". That was an understatement and it led me to a price that was not fair.

There is a complete partner dashboard, built on 18 June 2026 — the commit is called "Add SPAP partner dashboard with store/driver tracking and referral links". It has the partner's header and logo, four statistic tiles, a table of stores signed up, a table of drivers signed up, and its own referral links to copy. It is live right now.

It has no data. The page never asks the server anything — there is not a single request in it. The four numbers are zeros written into the page, and the tables say "will appear here" for ever. That is the same fault as the agent sign-ups: the screen was built, the wiring never was.

1 · Built and working

These exist and do their job today
  • The partner dashboard page itself — header, statistic tiles, stores table, drivers table, per-partner sign-up links, and a switch between partners through the web address.
  • The referral link capture. When a shop signs up through a partner's link, the partner's name is written onto that shop's record and kept. I checked the code that saves it.
  • The same for drivers, on both MsouWout and the MyPlopPlop delivery sign-up — the partner's name is sent with the registration.
  • A report on the server that counts drivers grouped by which partner brought them. It works. Nothing calls it.

2 · Built but disconnected

This is completing the implementation, not new work — no charge
  • The dashboard shows nothing. It has to ask the server for the stores and drivers carrying that partner's name, and put the real numbers in the tiles. The data is already being collected and the report already exists.
  • The partner list is written into the page. Only SPAP and FTPH/COTRASMOTHA are in it, as lines of code. Adding Église Shalom, Renaissance Ayiti or a university means editing the file. They need to be records you can add yourself.
  • There is no login. The page decides which partner you are from the web address. That is harmless while it shows nothing, and it must not stay that way once it shows real names and phone numbers. A partner has to sign in and see only their own.

I will do all three at no cost. The dashboard was paid for in June and it should have been finished then.

3 · Never built

This is the money layer, and it has never existed at organization level
  • An organization inside the commission engine. The engine knows individual agents only — there is no organization field anywhere in it. A partner's name on a shop record is a label; it is not connected to any commission.
  • An organization referral code that earns, as opposed to a link that labels.
  • Members belonging to an organization, with their own codes rolling up to it.
  • An organization wallet, organization payouts, and commission split between the organization and its member.

To be fair in both directions: no commission of any kind existed anywhere on the platform until this week — the counters were all zero. So this part is not something that was built and broke. It has genuinely never been there.

What I propose

Now, free: finish section 2. Real numbers on the partner dashboard, organizations you can add yourself, and a proper login. That gives FTPH, Église Shalom and Renaissance Ayiti working dashboards showing their real sign-ups.

Later, and only when you want it: section 3, the money layer — organization codes that earn, wallets, payouts and the split with members. 200 USD, not 400. I am not charging for section 2, and I should not have bundled the two together in the first place.

In the meantime nothing is blocked. Anyone from any of those organizations can sign up as an individual agent today at haitibiznis.com/koutye.html, be approved at haitibiznis.com/agents.html, and earn commissions properly from day one. What they will not have until section 3 is the organization earning on top.

Everything on this page was read from the code and the build history rather than from memory. Where I was wrong earlier, it says so.
