Production readiness — where the ecosystem actually stands

Checked 8 September 2026, against the live servers. Nothing below is from memory or from a test copy.

The short version. The parts you can see mostly work. What is missing is underneath: this is not one system. It is three separate databases in two different database engines, plus a fourth service that does not exist, plus a till that keeps its records on each phone. Nothing joins them, so the same person is a different, unconnected record in each one.

That is why problems keep appearing in a new place after being fixed in the last one. Until there is one identity shared across all of them, "one synchronised ecosystem" cannot be true no matter how many individual bugs get fixed.

Two things should be dealt with before anyone is onboarded, both marked in red below: MsouWout's admin routes are open to the public, and a live notification key is published in a public code repository.

1Every registration writes to the correct database problem

Every registration does write somewhere, and I found no lost records. The problem is where. There is no single place a person exists.

What is registeredWhere it is storedEngine
Customer, store, MyPlopPlop driver, Sòl group, agent sign-upMyPlopPlop databaseMongoDB

Consequences that are already visible: a driver who signs up on MsouWout is unknown to MyPlopPlop; approving him in one place does nothing in the other. The only thing linking a person across systems is their phone number, and it is not stored in the same format everywhere — that is the +509 work that is written, tested and still waiting for your go-ahead on MsouWout.

48HoursReady: I checked every likely address on 48hoursready-api.onrender.com today. All return "not found". The ambassador sign-up page is live and collects nothing. Anyone who fills it in gets an error.

2Referrals captured, commissions automatic not working

This one I can be exact about, because I counted the live records.

Live counts, 8 September
  • 19 people have signed up as agents through the referral page. The most recent was last night.
  • 19 of 19 are still marked pending. Not one has ever been approved.
  • 0 approved agent records exist.
  • 0 commissions. 0 payouts. 0 wallets. The tables are empty.

Nine of the nineteen did name the person who referred them, but that name is stored as free text someone typed — a first name, a nickname, sometimes a name with a year stuck on the end — not as a link to an account. So even once approval exists, there is nothing solid to pay a commission to.

There are also two different referral systems in the code. The one collecting these nineteen people is not the one with the commission logic in it. That needs a decision from you about which one is the real one before either can be finished.

3Dashboards show live, synchronised data partly

Each dashboard reads its own database directly, so what it shows is live and correct for that one system. None of them read across systems, so no screen anywhere shows you the whole picture. There is no screen that could tell you today how many people are on the platform, because there is no "the platform" to count.

The one place that is now genuinely live and cross-checked is the POS phone list, built this week.

4Payments end to end, with order, payout and commission records partly

  • MonCash / NatCash: the confirmation path is fixed and live. Both webhooks now ask the gateway to confirm before marking anything paid, and the buyer's way back from the gateway uses the address the gateway actually answers on. Before this it called an address that does not exist, got an HTML error page, and failed every single time — which is why no ticket was ever marked paid.
  • Tickets now also reconcile whenever the page is read, so a ticket cannot sit unpaid because a phone lost the redirect.
  • Card: there is a webhook route for it, but no card gateway is wired up to any of the buying screens. Card is not a working payment method today.
  • Payouts and commissions: escrow release exists and is now behind your console code. Commission records: none exist, as above.
Not tested, and it is the important one

No real end-to-end payment has been put through by me. I will not send real money through a live gateway, and I will not create fake orders in the database you are about to onboard people into. This needs you to buy one small real ticket and one small real order, and tell me the reference. Then I can prove the whole chain with real data. Until that happens, the payment chain is "believed correct", not "proven correct".

5Notifications delivered at the correct step not working

I read the notification code today. What it does when a ride, driver, ticket, refund or event comes in:

  • writes a line into the server log
  • posts to a webhook address, if one is configured
  • sends an email through a third-party form service

Two things follow from that. There is no WhatsApp sending and no SMS sending anywhere — the messages are written in WhatsApp style but nothing sends them. And every notification is addressed to you. The customer, the driver and the agent are never told anything by the system. No "your ticket is confirmed", no "your driver is on the way", no "your order has shipped".

6Search, filters and reports return accurate data not tested

Not audited. With the live record counts as low as they are (single figures in most tables), a search test now would prove very little. This is worth doing properly against real volume, and I would rather say "not tested" than give you a green tick I cannot stand behind.

7Admin permissions and sensitive endpoints one system open

I probed the live servers today with no credential, using impossible record ids so that nothing could be changed either way.

HaitiBiznis — all clear

11 of 11 sensitive endpoints refused. Escrow release, refunds, auto-release, deleting or rewriting anyone's event, approving a driver, the whole POS phone list and its block buttons, and the admin dashboard — all answer "forbidden" without the console code. The public event list no longer leaks organisers' MonCash and NatCash numbers or their email; I confirmed today that those fields are gone from the live response.

MsouWout — still open to anyone

Verified live today, with no credential at all:

  • GET /api/drivers answers 200 and returns every driver's name, phone, email, licence number and plate.
  • Driver approval is reachable with no credential — there is a locked route and an older unlocked one leading to the same records.
  • The national fare table can be rewritten with no credential.

The fix for this is written, tested and committed. It has not been pushed because you told me not to touch MsouWout until your ride test is finished, and I have kept to that. This is the single biggest risk on the list and it is waiting on one word from you.

A live key is published in a public code repository

All five code repositories are public. One of them has the private key for web push notifications written into a settings file in plain text. I confirmed it is the live key by comparing it against what the live server hands out — they match exactly. Anyone who reads that repository can send notifications to the ten phones currently subscribed, appearing as MyPlopPlop.

The repair is to generate a new key pair, move it into the server's private settings, and delete it from the code. The ten existing subscribers would need to open the app once to re-subscribe. Say the word and I will do it — it is free, and it is my mistake that it is there. I have not done it unasked because it changes something outward-facing.

One smaller item: an old admin password is also written into a settings file in the MsouWout repository. I tested it against the live server today — it is refused, so it is not the live one. It should still be deleted, because it looks live to anyone reading.

8Cross-platform synchronisation does not exist

There is no synchronisation between the seven products. There is no shared login, no shared customer record, and no message passed between the systems. Each one was built complete in itself.

This is the honest core of what you have been raising for months, and it is not a bug that can be fixed. It is a decision: pick one system as the place a person exists, and make the others ask it. Everything else on this page is small by comparison.

9Backup and recovery tested no backups

  • MyPlopPlop and HaitiBiznis share one MongoDB Atlas cluster on the free tier. The free tier has no scheduled backups. If that data is lost or corrupted there is nothing to restore from.
  • MsouWout is on a paid PostgreSQL plan, which does have backups. This is the one that is covered — and it is covered because it was learned the hard way: the original free database was automatically deleted after 30 days and took MsouWout offline from May until July.
  • No restore has ever been rehearsed. A backup nobody has restored from is a hope, not a backup.

10Performance with many users at once not tested

  • Not load tested. No test has ever been run with more than one user.
  • MyPlopPlop and HaitiBiznis servers are on Render's free plan. A free server goes to sleep after 15 minutes with nobody on it, and the next person to arrive waits roughly a minute for it to wake. To that person the app looks broken. When I measured today the servers were already awake and answered in under a second, so that number is the good case, not the bad one.
  • MsouWout is on a paid plan and does not sleep. That was a deliberate change for exactly this reason.
  • Onboarding thousands of people onto two free servers with no backups is the thing I would fix before the software.

11Mobile responsiveness tested, good

I loaded the eight main entry points at three phone sizes — a small Android (360px), an iPhone SE (375px) and an iPhone 14 (390px). That is 24 combinations. Every one loaded, and not one had the sideways-scrolling problem that makes a page unusable on a phone.

Limitation, stated plainly: this was done with a Chrome engine set to iPhone dimensions, not on a real iPhone. Safari on a real iPhone can differ. If you have an iPhone to hand, that is a ten-minute check worth doing.
